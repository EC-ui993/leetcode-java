# lc-0001 两数之和

## 思路

要找两个数加起来等于 target。暴力做法是枚举所有数对，瓶颈在于内层循环其实在反复回答同一个问题：
**「target - nums[i] 在不在数组里、下标是多少」**。

这本质是**查找**问题，不是**枚举**问题。查找就该交给哈希表，把 O(n) 的线性查找压成 O(1)。

关键转化：`a + b == target` ⟺ `b == target - a`。
所以遍历到 `a` 时，只要知道 `target - a` 之前出现过没有、在哪个下标，就够了。

## 复杂度

- 时间：O(n) —— 一次遍历，每次哈希查找均摊 O(1)
- 空间：O(n) —— 最坏情况哈希表存下全部元素

## 解法演进

1. **暴力双重循环 O(n²)**：对每个 `i` 再扫一遍 `j > i`。
   瓶颈很明确：内层循环在重复回答「某个值在不在数组里」，每次都是线性扫描。
2. **排序 + 双指针 O(n log n)**：先排序，再用左右指针逼近。
   但题目要返回**原下标**，排序会打乱下标，还得额外存一份「值 → 原下标」的映射——
   绕了一圈又回到哈希，而且整体仍是 O(n log n)，不如一步到位。
   （这个思路在 lc-0167 那种「输入已经有序」的场景才是正解。）
3. **一次遍历哈希表 O(n)**：边遍历边把 `nums[i] → i` 存进 map，同时查 `target - nums[i]`。
   **「边遍历边存」是这里的关键**——先建完整张表再查，会撞上「同一个元素用两次」的问题。

## 踩坑

- **不能先建完整张表再遍历**。反例：`nums = [3, 3]`、`target = 6`。先建表的话 map 里
  只剩 `3 → 1`（后写入的覆盖先写入的），查 `3` 得到下标 1，而当前 `i` 也是 1，
  于是返回 `[1, 1]` —— 同一个元素被用了两次。必须边查边存。
- 返回顺序是 `[小下标, 大下标]`，即 `[j, i]` 而不是 `[i, j]`，写反了过不了。
- `Map.get` 返回 `Integer`，判空要用 `!= null` 而不是 `!= 0`——
  下标 0 是合法值，拿 0 当「没找到」会漏掉第一个元素。
- 题目保证恰有一个答案，所以循环外的 `return` 只是为了让编译器满意。

## 关联题

- **lc-0167 两数之和 II**：输入**已有序**，正解是双指针、O(1) 额外空间。
  和本题对比着看，能直接看出「有序」这个前提能省掉整张哈希表。
- **lc-0015 三数之和 / lc-0018 四数之和**：排序 + 双指针 + 去重，是本题在有序场景下的推广。
- **lc-0454 四数相加 II**：把「两两分组 + 哈希计数」用到极致，是本题分组思想的升级版。
- 可迁移的模板：**「枚举 + 查找」→ 把查找换成哈希表**，能把一层 O(n) 降成 O(1)。
