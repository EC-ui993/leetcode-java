# lc-0128 最长连续序列

## 思路

一个连续序列，开头的数一定是最小的，可以利用这点来找到一个连续序列的开头数字，然后遍历哈希集合(set)，此时集合的数已经过去重处理，每个num都判断有没有num-1，没有说明该num所在的连续序列以它开头，最后一次次更新长连续序列得到结果

## 复杂度

- 时间：O(n)
  - 外层遍历去重后的 D 个元素
  - 内层 while 只对「序列起点」执行（`!set.contains(num-1)` 这个守卫），
    不是起点的元素被直接跳过
  - 所以内层总步数 = D − 段数，合计 ≤ 2D − 1 ≤ 2n − 1 < 2n
  - 直觉：**内层跑得越多，外层被跳过的次数就越多**，两者此消彼长
  - 反过来，去掉守卫、对每个元素都往后数，一个长度 n 的段就是
    n(n+1)/2 次操作，退化成 O(n²)。**所以这个守卫不是优化，是这道题的全部。**
- 空间：O(n) —— 哈希集合最多存 n 个元素
- 空间：O(n)

## 踩坑

看了题解之后，首先没想清楚set的作用，以为set是判断是否包括num-1后再加上去，发现行不通，后面知道set用来去重和判断，接着出现第二个问题：超时，原因是没维护变量currentNum，导致条件num+1一直成立，死循环，条件应该是currentNum+1，然后再currentNum++
